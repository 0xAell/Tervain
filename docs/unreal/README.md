# Porting Tervain to Unreal Engine

Tervain today is a browser game: TypeScript, Three.js and Vite, published to GitHub Pages. It stays the test bed while
the game is designed and tuned. The destination is Unreal Engine 5.9 and later, for a desktop release. This folder is
the bridge: what carries over, how each system maps, what the engine's web target can and cannot do, and the order of
work.

Nothing here has been run in Unreal Engine. The repository was prepared without the engine at hand, so every statement
about Unreal is one of three things, and says which: Epic's own words, quoted and checked against Epic's page; something
reported by others or seen only in a search result, and marked as not checked; or a plan of this project, to be tested
on the first machine that has the engine. [`sources.json`](sources.json) lists every source and every passage taken
from it. `npm run docs:sources` reads the pages again and looks for each passage. For this index and the system
mapping, conventions, web target and roadmap below, a test in CI keeps the register and the documents together, checks
every number that describes this repository against its data, and fails on a number or quotation that has no source and
is not marked as a plan. The engine names the C++ seed assumes have [a register of their own](engine-symbols.md), with
its own check, and the [review of the seed](seed-review.md) is a dated record of what was checked on its day.

## What the repository gives a port

| Piece | Where | What it is |
| --- | --- | --- |
| The engine-agnostic core | [`src/core`](../../src/core/README.md) | The game's data and rules in TypeScript with no renderer, browser or package dependency: state, commands, quests, residents and schedules, hostiles, animals, the hero's rules, the world's layout, terrain, water, planting. CI enforces the boundary. Its unit tests (`tests/core`, `tests/scenarios`) say what each rule must do. |
| Portable data | [`data/`](../../data/README.md) | The core's tables written as JSON with schemas, the terrain as Landscape rasters, and DataTable-shaped files in Unreal's units. Regenerated by `npm run data:export`; CI fails if it is stale. |
| The asset manifest | [`data/assets`](../../data/assets/README.md) | Every model, texture and sound with its source, licence, size, the Unreal asset it would become, and whether a port replaces, keeps or drops it, with the Fab pack named for everything that is replaced. |
| The Unreal project seed | [`unreal/`](../../unreal/README.md) | A source-only C++ project: row structs generated from the same definitions as the data, unit conversions, a data subsystem, and three rules mirrored as a worked example. Never built by the engine: CI compiles, links and runs it against small stand-ins for the engine names it uses, and [every engine name it assumes](engine-symbols.md) is checked against Epic's documentation, with what could not be checked. |
| The design | [`docs/vision.md`](../vision.md), [`docs/world`](../world/setting.md), [`docs/design`](../design/gameplay.md), [`docs/decisions.md`](../decisions.md) | What the game is meant to be, independent of any engine. |

## In this folder

- [System mapping](system-mapping.md): each system of the web build, where its rules and data live, and what it becomes
  in Unreal.
- [Conventions](conventions.md): units, axes, yaw, field of view, naming, levels of detail and how the data is imported.
- [The web target](web-target.md): what Unreal Engine 5.9's WebAssembly target is, what the mobile renderer it uses
  supports, and what that means for this game.
- [Roadmap](roadmap.md): the port in phases, each with what must be true before the next.
- [Review of the seed](seed-review.md): a scored review of what this repository gives a port, dated 16 November 2026,
  with the evidence for each score and what is missing from a ten.

## What carries over and what does not

- **Carries over as data:** everything under `data/`. Import it; do not retype it.
- **Carries over as rules to rewrite:** everything under `src/core/rules` and `src/core/game`. The TypeScript is the
  reference; its tests are the specification. `unreal/Source/Tervain/Public/Rules` shows the pattern.
- **Does not carry over:** the Three.js scene (`src/presentation`, `src/app.ts`), the browser adapters
  (`src/platform`), the Rapier binding (`src/physics`), and the web build's asset encodings. Unreal has its own
  renderer, input, physics, audio and packaging. The scene code remains useful as a description of what was built and
  why; the dated records under `docs/engineering` explain many of its choices.
- **Stand-ins to replace:** most models and surfaces (see the asset manifest).

The separate Gothic 3 study and reconstruction in this repository (`src/gothic3`, `assets/gothic3`, `public/gothic3`
and their tools and tests) is not part of Tervain and not part of the port. It shares no code with the game and is
compiled and tested apart from it; the [README](../../README.md#gothic-3-study-and-reconstruction) says how.
